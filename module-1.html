01 / WHY VERSION CONTROL

History is a feature.

Version control is a system for recording changes to files over time. Instead of passing around folders named project-final-final.zip, a team can inspect who changed what, when it changed, and why.

Git is distributed: every clone contains the project history, so you can create commits and inspect changes locally. This gives you a safe, deliberate rhythm: edit, stage, commit, then share.

03 / THE CORE OBJECTS

Four words unlock the workflow.

REPOSITORY

A project folder plus its tracked history.

COMMIT

A named snapshot of staged changes.

BRANCH

An independent line of development.

MERGE

Combining one line of history into another.
